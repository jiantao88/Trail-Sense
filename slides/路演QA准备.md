# Trail Sense AI Assistant · 路演 Q&A 准备

> 答辩规则：每组 8min（5min 路演 + 3min QA），现场严格计时。
> QA 只有 3 分钟，预计被问 3–5 个问题。下面按「最可能被问」排序，
> 每条给**一句话核心答**（脱口而出）+ **补充点**（被追问时展开）。
> 口播每题控制在 20–40 秒。

---

## 一、技术深度（最可能被问，评委想验证不是套壳）

### Q1. 为什么一定要端侧（on-device）？云端大模型不是更强吗？
**核心答**：因为我们的场景是户外——迷路、天气突变、夜间返程、受伤求救，恰恰是**没网或弱网**的时刻，云端 LLM 在关键时刻不可依赖。端侧还带来隐私（位置/照片不出设备）和低延迟。
**补充**：云端强，但「关键时刻用不了的强」对户外没意义；我们用 Gemma 4 在本地完成理解+推理+工具调度，0 云端 LLM 调用。

### Q2. 用的什么模型、怎么跑在手机上？延迟和体积如何？
**核心答**：Gemma 4，通过 **LiteRT-LM** runtime 在 Android 端侧推理，配合 `ModelManager` 做模型下载与管理，网络只用于一次性模型下载。
**补充**：推理子系统是 `AiInferenceSubsystem`；首包/响应延迟在可接受的交互范围内（现场 Demo 可实测）。如果被问具体数字，给你实测的 token/s 或秒数。

### Q3. function calling 是怎么实现的？是真调用工具还是模型编故事？
**核心答**：真调用。用 **Native Function Calling**：模型输出工具调用 → `TrailSenseAiToolRunner` / `ToolExecutorService` 执行 Trail Sense 本地工具 → 把真实读数回填给模型生成行动卡片。
**补充**：工具不是模型"想象"的，而是 App 里已有的导航/天气/信标/SOS 等真实模块；`AiAssistantTools` 是工具注册层。

### Q4. 怎么防止模型幻觉？给错的户外建议很危险。
**核心答**：三道防线——①工具调用拿的是**真实传感器读数**不是模型编的；②`ai_tool_knowledge.md` 工具知识库约束模型只用已有工具；③紧急场景输出**行动卡片 + 安全提示**，AI 是辅助判断不替代用户决策。
**补充**：我们定位是「降低判断成本」，最终行动由用户确认，不做不可逆的自动操作。

## 二、产品与差异化

### Q5. 这跟一个套了 Gemma 的 Chatbot 有什么区别？
**核心答**：区别在三层——场景（户外离线约束）、架构（端侧推理+本地工具执行）、交互（Agent Skill 把任务编排成工作流，不是单轮问答）。我们不是从零做 chatbot，而是给一个**成熟离线户外 App 加 AI 操作层**。
**补充**：壁垒不是接模型，而是把 AI 深度接进 12+ 个已有户外工具体系。

### Q6. Agent Skill 和普通 Prompt 有啥不一样？为什么需要它？
**核心答**：普通 prompt 是一问一答；Agent Skill（`ai_tool_skills.md`）封装的是「**完成一个户外任务的步骤**」，比如"迷路无信号"会编排 定位→路径→信标→SOS 一整套流程。
**补充**：调用链 `loadSkill(skillName) → runTrailSenseTool(toolId) → 本地结果 → 回答+行动卡片`。

### Q7. 多模态图片识别准确吗？典型用在哪？
**核心答**：图片是户外重要观察上下文。用户直接拍云层/环境/App 截图，经 Bitmap 处理后随 prompt 进 LiteRT-LM；典型场景是云层识别、截图解释、环境观察。
**补充**：价值是用户不用先把"看到的东西"翻译成专业术语，直接提交照片即可。

## 三、工程落地与开源（务必准备）

### Q8. 这是能跑的产品还是 PPT？
**核心答**：能跑。完整 Android/Kotlin 工程，有核心模块（`AiInferenceSubsystem`/`ModelManager`/`AiAssistantTools`/`TrailSenseAiToolRunner`）、测试、可安装 APK、Demo 视频和官方提交材料。现场可实机演示。

### Q9. Trail Sense 本身是开源项目，你们做了什么？（高频陷阱题）
**核心答**：Trail Sense 是成熟开源离线户外工具箱，提供了真实的工具资产；**我们的贡献是新增的 AI 操作层**——推理子系统、Native Function Calling、Agent Skill/知识库、多模态输入和行动卡片，这些是原项目没有的。
**补充**：诚实说明边界——原工具是地基，AI 编排与端侧推理是我们的工作。这样回答比含糊更得分。

### Q10. 耗电/性能怎么样？端侧推理是不是很吃资源？
**核心答**：模型只在用户主动提问时推理，非常驻；现场用充满电的机器实测流畅。
**补充**：如被追问，给出你测过的内存/发热表现，或说明可按机型选模型规格。

## 四、可能的开放性问题（准备方向即可）

- **下一步规划？** → 更多 Skill 覆盖、模型量化提速、可离线更新的知识库。
- **怎么验证用户真的需要？** → 户外场景的弱网/紧急特征是刚需来源；强调"低成本判断"这一真问题。
- **商业化/受众？** → 户外爱好者、应急、无网区域；产品是 Trail Sense 用户的能力升级。

## 现场 QA 应答原则

1. **先给结论，再补细节**——评委时间紧，第一句话就答到点。
2. **不知道就转化**——"这个我们没专门测，但相关的是 X"，不要硬编数字。
3. **守住一句话主张**："把户外工具箱从功能集合，升级为端侧 AI 户外助理。"
4. **3 分钟约等于 4–5 题**，每题别超 40 秒，给评委追问的空间。
5. 把 **Q3（真调用）/Q4（防幻觉）/Q9（开源边界）** 提前演练熟，这三题最容易翻车。
