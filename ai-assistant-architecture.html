1. 总体架构图

AI 助手由 UI、上下文、知识检索、Skill 执行、LiteRTLM 推理、工具调用和持久化几层组成。大模型运行在本地，通过 ToolProvider 可以反向调用 Trail Sense 工具。

2. 用户提问后的主流程

当前实现会在调用大模型之前，先由 UI 层尝试自动匹配一个 Skill 并执行其工具链；随后把工具结果、工具知识和上下文一起喂给大模型。

Flowchart
1

输入问题

用户在 AI Assistant 聊天界面输入文字，可附带图片或截图。

2

选择 Skill

AiToolExecutionService 使用 AiToolSkillMatcher 对可用 Skill 打分。

3

执行工具

若命中 Skill，则逐个运行 skill.toolIds 中声明的 Trail Sense 工具。

4

检索知识

AiToolKnowledgeService 合并 Skill 知识、工具知识与 User Guide 摘要。

5

构造 Prompt

AiPromptBuilder 拼接历史、工具结果、知识、上下文、图片提示和问题。

6

模型回答

AiInferenceSubsystem 调用本地 LiteRTLM 模型，并通过 callback 流式更新 UI。

4. Prompt 组装流程

User Prompt 是一个聚合容器，会把历史、工具结果、工具知识、当前工具上下文、图片说明和用户问题合成模型输入。

Prompt

System Prompt

定义 AI 助手身份、安全规则、语言要求、工具知识优先级、传感器读数不可编造等约束。

User Prompt Context

  • Recent chat history
  • Trail Sense tool results
  • Trail Sense tool knowledge
  • Context from current tool
  • Attached image hint
  • User question

模型输入

最终由 AiInferenceSubsystem 转成 LiteRTLM Content：图片会压缩成 JPEG bytes，文本作为 Content.Text 发送。

6. 关键代码入口

后续排查或扩展 AI 助手时，优先看这些文件和方法。

Code Map

主链路入口

  • AiAssistantFragment.sendMessage()：用户点击发送后的主流程。
  • AiInferenceSubsystem.initialize()：初始化 LiteRTLM Engine，GPU 失败回退 CPU。
  • AiInferenceSubsystem.createConversation()：注入 system prompt 和 tools。
  • AiInferenceSubsystem.sendMessage()：发送文本与图片给本地模型。

Skill / Tool 入口

  • AiToolExecutionService.selectSkill()：对 Skill 打分并选择最佳工作流。
  • AiToolExecutionService.executeStepByStep()：逐步执行工具并更新工具卡片。
  • AiAssistantTools.loadSkill()：暴露给 LLM 的 Skill 加载工具。
  • AiAssistantTools.runTrailSenseTool()：暴露给 LLM 的 Trail Sense 工具调用入口。
  • TrailSenseAiToolRunner.run()：按 Tools.ID 读取或准备具体工具数据。
核心结论：这套 AI 助手采用「本地大模型 + RAG 式工具知识 + Skill 工作流 + Trail Sense 工具读取」的混合架构。它不是单纯聊天机器人，而是在发送给大模型前尽量把可验证的工具数据和工作流约束写入 Prompt，同时保留 LiteRTLM ToolProvider 让模型在需要时主动调用工具。
